# ADR 0009：用詞、AI 員工的子頁與視覺統一

- 狀態：Accepted
- 日期：2026-11-26
- 決定者：@BenTsai0212
- 相關：#177、[設計規格 v5](../design/v5/knowledge-crew-design-v5.md)、[設計規格 v4](../design/v4/knowledge-crew-design-v4.md)、RFC 0001、ADR 0002、ADR 0007、ADR 0008

## 背景

第 5 階段之後，畫面上的概念約有 12 個，驗收面板的交件被推到第 2 個畫面以後；knowledge-kit 與 AI 員工的畫面各有一套寫法。設計規格 v4 統一了外框與元件，v5 再把文字減少、用詞改從使用者的角度取。

用詞原本從系統的角度取：「信任」「層級」「看重點」「要看的重點」「獨立檢查」。使用者要先懂規則才看得懂畫面。

## 決定

### 一、用詞

介面、README 與之後的文件使用新用詞。程式識別名稱（`trust/`、`light`、`relax`、`revoke`、`spotCheck` 等）、資料表與欄位不改。

| 原本 | 改成 | 英文 |
| --- | --- | --- |
| 信任（功能名、頁名） | 審查方式；理念改用標語「做對越多，看得越少」 | Review mode |
| 逐項看 | 全部看 | Check everything |
| 看重點 | 只看標記處 | Check marked spots |
| 要看的重點 | 請你確認（「Rowan 請你確認 2 處」） | 第 5 張 Issue 決定 |
| 層級 | 不用這個詞，直接寫「全部看」或「只看標記處」 | — |
| 事後更正、通過後發現有錯 | 補記錯誤；入口寫「通過後發現錯誤？」 | 第 5 張 Issue 決定 |
| 獨立檢查、自動檢查 | 系統檢查 | 第 5 張 Issue 決定 |
| 守則的確認、修改後確認 | 採用、改寫後採用 | 第 5 張 Issue 決定 |
| 工作帳本 | 紀錄 | 第 5 張 Issue 決定 |
| 回流知識 | 收進知識庫 | 第 5 張 Issue 決定 |

完整對照與其他用詞見設計規格 v5 第 2 節。驗收、交件、退回、守則、交辦、抽查不改；知識庫的審核／核准／退回不改。

### 二、AI 員工的子頁

由 6 個（總覽、員工、交辦、工作與驗收、信任、工作帳本）改為 4 個：

| 子頁 | 內容 | 原本 |
| --- | --- | --- |
| 工作 | 待驗收清單與驗收面板；「清單｜看板」切換 | 工作與驗收、總覽 |
| 員工 | 每位員工的審查方式、最近 10 次、守則 | 員工、信任的每類工作卡 |
| 交辦 | 交辦表單、最近交辦 | 交辦 |
| 紀錄 | 事件；「看統計」切換成統計表 | 工作帳本、信任的總表 |

審查方式依「員工 × 工作類型」計算（`trust/rules.ts`）不變。demo 的每位員工只負責一種工作，員工卡直接顯示；之後一位員工負責多種工作時，員工卡依工作類型分列。

### 三、寫作規則與字數預算

依設計規格 v5 第 4 節：一個畫面只回答一個問題；狀態用圖示與徽章表達；說明只放在「?」裡或第一次遇到時說一次；列表只放和決定有關的；首頁與驗收面板第一個畫面 200 字內（不含交件本文）。

### 四、外框與元件

依設計規格 v4 第 4、5 節（v5 第 5 節取代其中不同的元件）：

- 每頁一個主標題（`h1`）；AI 員工子頁上方小字「AI 員工」。
- 手機底部分頁列：首頁、問答、圖譜、AI 員工、更多（時間軸移到「更多」）。
- `client/theme.json` 新增 `borderStrong`（Light `#7E8691`、Dark `#5A6782`），用於輸入框、次要按鈕與虛線框。
- 「最近的變化」：側欄與手機頂端列的鈴鐺打開面板，首頁列最近 3 則；鈴鐺不顯示數字（不記錄已讀）。
- 導覽改為 5 步：今天的工作、驗收、退回、審查方式、收進知識庫。

### 五、knowledge-kit 的畫面

範圍包括 knowledge-kit 的畫面（登入、問答、圖譜、時間軸、上傳、待審、評測台）。這會改到上游的檔案（ADR 0002），同步上游時可能衝突。降低衝突的做法：

- 視覺優先放在 token（`client/theme.json`）與共用 CSS；元件結構只在畫面需要時改。
- 每個 PR 在說明中列出改到的 knowledge-kit 檔案（沿用現行做法）。
- 同步上游時，視覺以本 repo 為準；上游的功能變更照常合併。

### 六、規格的優先順序

ADR 與 `## 決定` ＞ 設計規格 v5 ＞ 設計規格 v4 ＞ HTML 原型的細節。v5 的 HTML 是驗收畫面的依據；HTML 沒畫到的狀態依規格文字。

## 不能動的規則（換了用詞之後）

依設計規格 v5 第 7 節。四項必要功能的意思不變：

- 員工標出要看的地方：「○○ 請你確認 N 處」，在驗收面板最上面。
- 一次做錯了就改回：退回選項寫「做錯了・會改回全部看」。
- 改為只看標記處要人同意、可以收回：員工卡的「改為只看標記處」「改回全部看」。
- 抽查不能關掉：徽章「抽查：這次全部看」，沒有關閉按鈕。

退回原因三選一不變；選項上原本寫「影響信任」，改為直接寫後果（「會改回全部看」「審查方式不變」）。

## 後果

- 介面文字、e2e 依文字找元件的測試、`app/src/crew/i18n.test.ts` 的舊用詞檢查、導覽、README 截圖都要跟著改（Epic #176 的子 Issue）。
- RFC 0001、ADR 0007、ADR 0008、設計規格 v3 保留原本的用詞，各加一行註記指到本 ADR。
- 研究主張與研究文件之後改用新用詞。
